# 店家Mobile App前端功能白皮書

# 0) 整體設計風格

- **視覺**：純白設計，風格類似 ChatGPT 或 Threads，簡約流暢。
- **動效**：以「適時的流暢動畫」提升質感。
- 整體設計風格與顧客端 Mobile App 基本一致。

---

# 1) 註冊 / 登入頁（啟動後最先顯示）

## 1.0 進入與動效

- 完成下載並開啟 App 後，最先顯示「註冊登入頁」。
- **品牌 Logo** 先置中顯示，接著**慢慢往上移動**；Logo 下方**浮出 Email 與密碼輸入**。
- 按下「登入」進入 **CurrentOrders** 頁。
- **Email 為唯一登入方式**。
- 若尚未有帳號，點擊下方「註冊」小鍵進入註冊（臨時頁面，分三部分）。

## 1.1 註冊流程（臨時頁面：分三部分）

### （一）Email 驗證

- 輸入 Email，按「發送驗證碼」。收到後填入驗證碼欄位並按「驗證」。
- 若未收到，**在每次按「發送驗證碼」30 秒後**可按「重新送出驗證碼」。
- **裝置上限**：每個裝置在此 App **至多送出二十次**驗證碼，超過則鎖定不予驗證。

### （二）電話驗證

- 與 Email 驗證類似：輸入手機號碼 →「發送驗證碼」→ 填入 →「驗證」。
- 若未收到，**在每次按「發送驗證碼」兩分鐘秒後**可按「重新送出驗證碼」。
- **裝置上限**：每個裝置在此 App **至多送出五次**驗證碼，超過則鎖定不予驗證。

### （三）密碼設定

- 輸入「設定密碼」與「確認密碼」，按下註冊即完成並**直接登入**，進入 Current**Orders** 頁。

## 1.2 註冊限制與文案

- **同一 Email / 同一手機號碼**在此 App **都只能註冊一個帳號**。
- **同一部手機**在此 App **也只能註冊一次帳號**。
- 若在使用這次註冊資格前曾登入過其他既有帳號，**本次註冊資格會喪失**。
- 註冊頁面需小而清楚顯示文案：
    
    「**為了避免帳號的濫用，一個 Email / 一隻手機號碼都只能註冊一隻帳號；一部手機也只能註冊一次帳號。敬請愛惜您的帳號。**」
    

## 1.3 模擬器不可用（及開發期間處理）

- **必須確保模擬機無法使用 App**（正式環境）：
    1. 官方驗證服務
        - Android：**Google Play Integrity API**
        - iOS：**Apple App Attest / DeviceCheck**
        - → 驗證結果傳到後端，由後端決定是否放行
    2. **硬體金鑰**：手機在 Secure Enclave / Keystore 生成金鑰；伺服器隨機出題，手機以該金鑰簽名過關
    3. **驗證碼 / Captcha**：註冊或登入加入 **reCAPTCHA / Cloudflare Turnstile**
- **開發期間**需提供替代措施或暫時關閉模擬器檢驗，因為需以電腦測試與 `flutter run` 跑模擬。

# 2) 首次登入後的「初始資料」臨時頁面（不可跳過）

- 進入CurrentOrders 頁後，在註冊後的第一次登入會跳出一個初始資料用的臨時頁面，這個臨時頁面分兩個部分。

### （一）**輸入店家基本資料**

- 請用戶先輸入自己的店名、地址、Google Maps連結、營業時間。

### （二）營業登記驗證

- 請用戶先輸入自己的統一編號、登記名稱、登記地址和負責人姓名。

### （三）食品業者登錄驗證

- 請用戶先輸入自己的食品業者登錄字號。

### （四）建立菜單

- 讓顧客上傳菜單，自動轉換成可編輯的內建菜單，再進行小幅手動調整

### （五）銀行帳簿正面（外加手動輸入帳號）

- 會需要用戶備妥銀行帳簿。
- 然後請用戶清楚地拍銀行帳簿正面（外加手動輸入帳號）（直接調用用戶相機拍照，不讓用戶上傳已經拍好的照片）

- 初始資料的臨時頁面不能跳過。
- 但也要做開發期間的替代措施（如手動上傳照片）。因為在開發期間我們要用電腦來測試和flutter run跑模擬，沒辦法直接調用系統相機。

# 4) CurrentOrders 頁（接單主頁）

> 本頁以四個頁籤呈現不同階段的訂單：待確認 → 待接單 → 備餐中 → 已取餐。
> 
> 
> 核心原則：**顧客外送費為「自訂價格」；訂單需經市場媒合。店家只有在外送員接單後才開始備餐**。
> 

### 4.0 共同設計規格（四個頁籤通用）

- **列表卡片資訊（最小欄位）**：訂單編號、下單時間、顧客暱稱、餐點摘要（品項×數量）、餐費小計、顧客自訂外送費、取餐地址（店家）、送達大略區域（僅顯示里/路段以保護隱私）、顧客備註（過敏/不加辣…）。
- **卡片動作**：點卡片開「訂單詳情臨時頁」；主要按鈕依狀態不同（見各分頁）。
- **詳情臨時頁固定段落**：品項與份量、包裝體積/重量估算（是否一趟載得下）、顧客外送費、預估店—客直線距離與路線時間、顧客/店家備註、時間軸（事件紀錄）。
- **即時同步**：新單插入/卡片移動/倒數計時皆需**動畫過渡與位置鎖定**，避免操作誤觸（例如列表穩定策略：僅在卡片外區塊淡入/淡出，保留使用者觸控目標）。
- **錯誤/例外**：網路中斷顯示離線條；動作採**樂觀更新 + 失敗回滾**；所有取消需選原因。
- **搜尋/篩選（右上角）**：輸入訂單編號、日期、狀態；篩選含「大體積/大重量」訂單。

---

### 4.1「待確認」頁籤（新進訂單）

**狀態意義**：顧客剛下單，尚未送去媒合。店家需確認**存貨**、**載運量是否一趟可載**、並填寫**預期備餐時間**。

**主要卡片按鈕**：`確認可接`、`無法接單（取消）`

1. **卡片額外欄位**
- 倒數：顧客等候店家確認倒數（例如 5–10 分鐘內提示，逾時顧客端會看到「等待店家確認」）。
- **容量提醒**：依菜單品項的「體積/重量等級×數量」估算是否超過單趟上限（以等級或「袋位」估算）。若疑似過大，卡片顯示**「可能超過外送員載運上限」**警示。
1. **確認流程（臨時頁步驟）**
- **A. 存貨核對**：逐品項勾選是否可出；若缺貨可改同價替代（需顧客同意）或直接取消。
- **B. 載運量檢查**：顯示系統估算結果；若超過，提供「建議拆單」提示（系統會自動複製成兩張訂單、維持原外送費分攤標示；*僅提示，不更動顧客外送費*）。
- **C. 預期備餐時間**：輸入分鐘數（例如 10/15/20…），僅用於媒合展示與接單承諾；**此階段仍不可開始備餐**。
- **D. 備註**：可補充說明（例：現煎需久、需保溫袋等）。
- 送出後狀態轉為 **「待接單」**；時間軸新增「店家已確認（備餐時間 X 分）」。
1. **取消（無法接單）**
- 需選原因（缺料／人手不足／營業時間外／其他）；顧客端收通知，訂單結束並入歷史（未成交）。

---

### 4.2「待接單」頁籤（媒合中）

**狀態意義**：訂單已廣播給周邊活躍外送員（H3 商圈邏輯）。仍**不可開始備餐**。

**主要卡片按鈕**：`調整備餐時間`、`取消訂單`、（僅資訊）**接單機率指標**

1. **卡片額外欄位**
- **媒合進度**：附近活躍外送員數、已曝光次數、預估接單機率（依外送費 vs 商圈分佈、距離、備餐時間推估）。
- 倒數：系統建議等待時間（逾時將提示顧客調整外送費或取消）。
1. **可執行動作**
- **調整備餐時間**（±5 分為步進；更新後同步到外送員端卡片）。
- **取消訂單**（同 4.1 規則）。
- **查看詳情**：顯示預估路線、費率分佈、容量估算。
1. **狀態轉換**
- **外送員接單** → 自動移入「**備餐中**」，並推播「已有人接單，請開始備餐」。
- **顧客主動取消 / 系統逾時未接** → 訂單結束並移入歷史（未成交）。

---

### 4.3「備餐中」頁籤（已有人接，開始備餐）

**狀態意義**：外送員已接單，店家此時**開始備餐**。

**主要卡片按鈕**：`我備好囉`、`需要更多時間`、`聯絡外送員`、`取消（特殊）`

1. **卡片額外欄位**
- **外送員資訊**：暱稱、評分、近七日完成單數、交通工具、到店 ETA 倒數、即時距離（地圖縮圖可展開）。
- **承諾取餐時間**：以「店家填寫的備餐時間 + 接單時間」計算；若延誤，卡片顯示紅色逾時條並可一鍵「需要更多時間（+5/+10）」。
- **容量提醒**：若先前判定可能超量，提示「請分袋標記」與交接說明。
1. **可執行動作**
- **我備好囉**：外送員端收到「可到店取餐」提醒；到店後，外送員可掃描/輸入取餐碼完成交接。
- **需要更多時間**：增加 X 分鐘並同步給外送員。
- **聯絡外送員**：遮罩電話或訊息（雙向保護）。
- **取消（特殊）**：僅在**重大突發**（停電/設備故障）可用；需選原因並通知外送員與顧客。
1. **狀態轉換**
- 外送員在店端完成交接 → 轉 **「已取餐」**。

---

### 4.4「已取餐」頁籤（外送員已取餐、配送中）

**狀態意義**：餐點已交接，配送進行中。

**主要卡片按鈕**：`問題通報`、`查看路線`

- **展示**：外送員前往顧客 ETA、路線縮圖、顧客收餐驗證方式（收餐碼／簽收）。
- **問題通報**：例如「外送員取錯」「忘記附贈湯」→ 建立客服事件，關聯訂單編號與時間軸。
- **狀態終結**：外送員完成送達 → 訂單移入 **OrderHistory**（已完成）；若顧客取消/退貨等，則附註於歷史詳情。

# 5) **OrderHistory頁**（歷史訂單）

> 用於查詢已完成／已取消／未成交（未媒合）等所有歷史紀錄與明細。
> 

### 5.1 功能區塊

- **時間範圍**：今日 / 本週 / 本月 / 自訂（日期區間）。
- **狀態篩選**：已完成、店家取消、顧客取消、未媒合（等待期滿未接單）。
- **搜尋**：訂單編號、顧客暱稱、品項關鍵字。
- **匯出**：CSV（欄位：日期、編號、狀態、餐費、顧客外送費、備餐時間、完成時間、取消原因、備註）。
- 列表卡片：顯示**狀態標籤**與**總時長**（下單→送達）。

### 5.2 訂單詳情（臨時頁）

- **基本**：編號、下單時間、完成/取消時間、狀態、顧客外送費（展示，店家不可更動）、餐費合計、付款方式（例如現金；*僅展示*）、顧客/店家備註。
- **餐點**：品項、單價、數量、是否大體積/重量（供回顧）。
- **時間軸**：顧客下單 → 店家確認 → 廣播開始（待接單）→ 外送員接單 → 到店取餐 → 送達/結束；若未媒合/取消，標註原因。
- **支援**：`問題申訴`、`聯絡客服`（附帶此詳情快照）。

# 7) MenuManagement**頁**（菜單編輯）

> 經由類別 → 品項清單 → 品項編輯的三級結構管理菜單，並提供容量/重量等欄位以支援「一趟能否載下」的前置判斷。
> 

### 7.1 類別（Categories）

- 列表與排序（拖拉），顯示上架/下架開關。
- 動作：新增類別、重新命名、調序、隱藏。

### 7.2 品項清單（Items）

- 顯示：縮圖、名稱、售價、是否上架、今日剩餘庫存、預設備餐時間、容量/重量等級標籤。
- 批次動作：上/下架、移動到其他類別、複製、多選刪除。

### 7.3 品項編輯（表單欄位）

- **基本**：名稱、售價、照片、說明。
- **備餐**：**預設備餐時間（分）**，顯示到接單頁供外送員評估。
- **容量/重量**（用於載運判斷）：
    - **體積等級**：V1 / V2 / V3 / V4（從小到大；例如：V1=單份飯類、V3=多飲料組、V4=大鍋餐盒）。
    - **重量等級**：W1 / W2 / W3 / W4（從輕到重）。
    - 前端僅做等級選取與提示；**媒合與待確認步驟會用「等級×數量」估算是否超出單趟上限**並顯示提醒。
- **選配/加購**：單選/多選、必選/可選、加價金額、最多/最少可選數。
- **庫存**：每日可售數、目前餘量、自動售罄開關（售罄自動下架或顯示「今日售完」）。
- **上架**：立即上架/存草稿；預覽「顧客端呈現」。
- **安全**：變更需再次確認；離開未存提示。

### 7.4 店家營業狀態聯動

- **「暫停點餐」總開關**（全店下架顧客端僅顯示暫停營業）；
- 營業時間外自動禁止新單；手動可提前暫停或提前恢復。

# 8) **Account頁**（帳號）

> 管理店家基本資料、營業狀態、驗證與通知設定等。
> 

### 8.1 店家資料

- **基本資料**：店名、門市地址、Google Maps 連結、電話、營業時間、外帶/內用備註。
- **驗證狀態**：食品業者登錄字號、（若有）營業登記、影像實證審核結果與到期提醒。
- **顧客端呈現預覽**：店鋪封面、描述、營業時間顯示。

### 8.2 營業與接單

- **營業狀態開關**：營業中 / 休息中；
- **暫停接單**（僅影響外送單，不改變一般營業）；可設定暫停時段（例如 30/60 分）與自動恢復。

### 8.3 通知與裝置

- **推播**：新單提醒、接單成功、外送員到店、送達、逾時/取消；可逐項開/關與聲音/震動。
- **裝置安全**：裝置綁定、最近登入紀錄、可撤銷異常裝置。

### 8.4 金融與文件

- **收款帳戶/撥款資訊**（僅展示狀態與遮罩帳號，修改需再次驗證）。
- **文件管理**：重新上傳/更新（食安字號、營業登記等），顯示審核中/通過/退回原因。

### 8.5 其他

- **客服與回饋**：常見問題、聯絡客服、問題回報（關聯最近一張訂單）。
- **系統**：App 版本、更新日誌、清快取、登出。

---

## 事件與狀態（前端對齊用，簡表）

- **主要狀態**：`PENDING_CONFIRM`（待確認）→ `PENDING_COURIER`（待接單）→ `PREPARING`（備餐中）→ `PICKED_UP`（已取餐）→ `DELIVERED`（完成）／`CANCELLED_*`（取消）／`EXPIRED_UNMATCHED`（未媒合）。
- **關鍵事件**：`merchant_confirm(stock_ok, volume_ok, prep_minutes)`、`courier_accepted()`、`prep_ready()`、`handover_done()`、`delivered()`、`cancel(reason)`、`extend_prep(+minutes)`。
- **時間軸**：所有事件都寫入，供 OrderHistory 顯示與申訴比對。
