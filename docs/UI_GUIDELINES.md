# 前端設計風格／UI 規範

> 目標：讓所有前端輸出維持 純白、流暢、簡潔、高級 的 ChatGPT 式體驗。此規範為「唯一事實來源」，所有頁面與元件必須依此實作；若規範與需求衝突，以規範為準並提交 ADR 說明。
>

---

## 1. 設計原則（Design Principles）

1. **純白為底**：畫面主要背景為白色，僅用極淺灰做分層，避免圖案或高彩度背景。
2. **呼吸感優先**：留白 > 裝飾。任何元件周圍需有足夠空間，避免擁擠。
3. **專注內容**：排版以易讀為主；用色、線條、陰影只為服務資訊層級。
4. **一致即美**：同類元件在不同頁面呈現必須一致（樣式、尺寸、互動）。
5. **精緻但克制**：動畫與過渡只為輔助，不做花哨效果；時長短、曲線自然。
6. **可擴展**：所有樣式由設計 Token 驅動；嚴禁頁內自創顏色、邏輯性間距。

---

## 2. 設計 Token（Design Tokens）

> 不得在頁面或元件內硬編碼顏色／間距／圓角／陰影。
>

### 2.1 顏色（Light Mode 基礎）

- `-bg`：#FFFFFF（主背景）
- `-bg-subtle`：#FAFAFA（區塊次背景、大面積分層）
- `-border`：#E5E7EB（分隔線、邊框）
- `-text-primary`：#0F172A（深色文字）
- `-text-secondary`：#475569（次要文字）
- `-text-muted`：#94A3B8（提示／佔位字）
- `-brand`：#0EA5E9（品牌互動色，低飽和藍；不可大面積鋪色）
- `-accent`：#10B981（完成狀態、成功）
- `-warn`：#F59E0B（警示、提醒）
- `-danger`：#EF4444（錯誤、破壞性行為）
- `-focus-ring`：#93C5FD（聚焦可見化）

> 深色模式（若後續開啟）僅在 Token 層替換等價色，不改元件結構。
>

### 2.2 字體與排版

- 系統字體堆疊（Web）：`ui-sans-serif, system-ui, -apple-system, "Noto Sans TC", "Segoe UI", Roboto, Arial, "Apple Color Emoji", "Segoe UI Emoji"`
- 行高（paragraph）：1.6；標題行高：1.25。
- 字級（REM）：
    - `-fs-2xl: 1.5rem`（頁面標題）
    - `-fs-xl: 1.25rem`（區塊標題）
    - `-fs-lg: 1.125rem`（重點文）
    - `-fs-md: 1rem`（一般文字）
    - `-fs-sm: 0.875rem`（輔助說明）
    - `-fs-xs: 0.75rem`（備註、微文）

### 2.3 間距（Spacing Scale, 8pt 基準）

- `-sp-0: 0`
- `-sp-1: 4px`（極微）
- `-sp-2: 8px`
- `-sp-3: 12px`
- `-sp-4: 16px`
- `-sp-5: 20px`
- `-sp-6: 24px`
- `-sp-8: 32px`
- `-sp-10: 40px`
- `-sp-12: 48px`

### 2.4 圓角、邊框、陰影

- 圓角：`-radius-sm: 6px`、`-radius-md: 10px`、`-radius-lg: 16px`（卡片、輸入框、按鈕使用 md 為預設）。
- 邊框：1px 實線，顏色 `-border`。
- 陰影：
    - `-shadow-sm`: 0 1px 2px rgba(0,0,0,0.04)
    - `-shadow-md`: 0 4px 16px rgba(0,0,0,0.06)
    - `-shadow-lg`: 0 10px 30px rgba(0,0,0,0.08)

### 2.5 動畫（Motion）

- 時長：`-dur-fast: 120ms`、`-dur-base: 180ms`、`-dur-slow: 240ms`
- 緩動：`-ease-standard: cubic-bezier(0.2, 0, 0, 1)`（加速快、減速柔）
- 原則：只在 **出現／消失／狀態切換** 上使用，位移 < 12px，透明度變化 0→1。

---

## 3. 佈局與排版（Layout）

1. **內容寬度**：桌機頁面主欄最大寬度 `~960–1040px`；兩側留白自適應。
2. **區塊分層**：以留白與輕邊框為主；卡片僅在需要聚焦或容器概念時使用。
3. **群組節奏**：區塊之間使用 `-sp-8` 或 `-sp-10`；同區塊內標題與內容距離 `-sp-4`。
4. **網格**：行內使用 12 欄網格（桌機）；平板 8 欄；手機單欄或 4 欄。
5. **響應式**：
    - 手機 <768px：單欄，字級不要低於 `-fs-sm`。
    - 平板 768–1024px：主欄 + 次欄（可折疊）。
    - 桌機 ≥1024px：主欄最大寬度，右側可用輔助欄（固定 280–320px）。

## 4. 元件（Components）

> 所有元件必須以 Token 實作，不得自行寫 inline style 顏色/尺寸。
>

### 4.1 按鈕（Button）

- 類型：Primary（品牌色填色）、Secondary（白底邊框）、Tertiary（純文字）。
- 尺寸：M（40–44px 高）為預設，L（48px 高）用於主流程。
- 狀態：default / hover / active / disabled / loading；loading 使用旋轉微動，文案保留。
- 邊角：`-radius-md`；陰影僅在浮動主按鈕使用 `-shadow-sm`。

### 4.2 輸入（Input / Select / Textarea）

- 高度 40–44px；左右內距 `-sp-4`。
- 聚焦：1px 邊框換 `-brand`，外圍加 `-focus-ring` 24% 透明外光。
- 佔位字顏色使用 `-text-muted`，不可用深色。

### 4.3 卡片（Card）

- 白底、1px 邊框、`-radius-md`、`-shadow-sm`（可選）。
- 卡片標題字級 `-fs-lg`；內容 `-fs-md`；內距 `-sp-6`。

### 4.4 清單與表格（List / Table）

- 交錯底色不允許；以分隔線 `-border` 區隔。
- 表頭字重中等；行高寬鬆（≥ `-sp-6`）。
- 空狀態需有圖示/說明文字 + 主按鈕（引導下一步）。

### 4.5 對話框（Modal / Drawer）

- 遮罩透明黑 `rgba(15,23,42,0.4)`；容器白底、`-radius-lg`、`-shadow-lg`。
- 進場：上浮 8–12px + 透明度 0→1（`-dur-base`）。
- 內容垂直節奏：標題下 `-sp-4`，主區塊與按鈕群 `-sp-6`。

### 4.6 分頁／標籤（Tabs）

- 底線式（underline）為預設；活躍態用品牌色細線（2px），字色 `-text-primary`。

### 4.7 狀態元件（Badge / Chip / Toast）

- Badge：極簡，字級 `-fs-xs`、圓角 `-radius-sm`、淺底 + 深字。
- Toast：右上淡入，卡片樣式 `-shadow-md`，3 秒自動關閉。

### 4.8 Skeleton / Loading

- Skeleton 使用 `-bg-subtle` 條紋閃動（線性漸層），時長 `-dur-slow`。
- Spinner 僅在按鈕/區塊 loading 使用，小而不突兀。

### 4.9 空／錯誤／成功狀態（Empty / Error / Success）

- 空：簡單線性圖示 + 一句描述 + 動作按鈕。
- 錯：紅色圖示 + 清楚行動建議（重試 / 回上一頁 / 聯絡支持）。
- 成：綠色圖示 + 重要資訊摘要；避免彈窗濫用。

---

## 5. 互動與動作（Interaction）

1. **Hover/Active**：只有可互動元素才有 hover；active 壓下 2–4px 位移或陰影縮小。
2. **鍵盤可達**：Tab 走訪順序與視覺順序一致；焦點可見（`-focus-ring`）。
3. **點擊區域**：可點元素的可點區 ≥ 40×40px。
4. **錯誤提示**：就近呈現，紅字 + 輕微晃動（可選，但幅度極小）。
5. **確認動作**：破壞性操作需二次確認；主要按鈕文案使用動詞開頭。

---

## 6. 無障礙（A11y）

- 對比度：文字與背景對比度 AA（一般文字 ≥ 4.5:1、標題/粗體 ≥ 3:1）。
- ARIA：互動元件補足 ARIA 屬性；表單控制需關聯 label。
- 鍵盤：全站可用鍵盤完成主要操作。
- 動畫偏好：尊重 `prefers-reduced-motion`，在此模式下移除位移、僅保留淡入。

---

## 7. 文案規範（Microcopy）

- 語氣中性、克制、直接；避免驚嘆號與行話。
- 標題 6–10 字、按鈕 2–4 字；錯誤訊息說出**原因 + 行動**。
- 佔位提示要描述目標而非範例（例：`輸入店名` 而非 `例如：小王牛肉麵`）。

---

## 8. 程式實作規範（給工程）

1. **樣式來源**：只允許使用設計 Token（CSS 變數／Tailwind 自定義主題／Flutter Theme）。
2. **組件庫**：建立 `ui/` 下的基礎元件（Button, Input, Card, Modal, Tabs, Table, Skeleton, Toast）。頁面不得直寫 HTML + 自創 class。
3. **狀態機**：每個頁面/流程需列出 `idle/loading/success/error/empty` 狀態與對應視圖。
4. **測試**：針對視覺回歸（快照）、互動（可點、可達）、無障礙（可聚焦）做最小測試。
5. **命名**：類名/檔名採語義化（`OrderList`, `MerchantCard`），避免縮寫。

---

## 9. 不可為（Non‑Goals / 禁忌）

- 禁止大面積使用品牌色作為背景。
- 禁止濫用陰影（超過 `-shadow-md` 僅允許在彈窗）。
- 禁止使用高彩度、飽和對比強烈的配色。
- 禁止在頁面內硬編碼顏色、間距、字級；不得擅自新增色票。
- 禁止在同頁內混用多種元件風格（例如同時出現圓角 6px 與 20px）。

---

## 10. 交付檢查清單（DoD）

- [ ]  使用 Token；無硬編碼樣式。
- [ ]  響應式在手機/桌機均無破版。
- [ ]  可達性：Tab 導覽可見、對比度達標。
- [ ]  空／載入／錯誤狀態齊全。
- [ ]  元件與其他頁一致（樣式、尺寸、互動）。
- [ ]  動畫時長與曲線符合規範。
- [ ]  通過快照/視覺回歸基本測試。
